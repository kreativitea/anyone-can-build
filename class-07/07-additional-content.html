Class 7 — Additional content

Assigned after class, on top of the syllabus outside-work: do it before next week. It takes about twenty-five minutes. This week's main homework is on the Class 8 page, so this one is short.

Try

  • Peter Cottle, Learn Git Branching (~15 min for three levels; free, no account). The four words from the README slides, commit, branch, main and merge, as a drawing that changes when you type a command. Do the first three levels, Introduction to Git Commits, Branching in Git and Merging in Git, and stop before the fourth, Rebase, which this course does not use. Where a level says git checkout, type git switch instead. It works there too, and it is the command from class: git switch -c bugFix makes a branch and moves you onto it. Watch the two merges in the third level. The first makes a new commit with two parents, because both lines have new work on them. The second only moves a branch forward, because that branch has nothing new. On Friday, main had nothing new, so the merge only moved it forward: the second case.
  • CommonMark, Markdown Tutorial (~10 min; free, no account). Ten short lessons, each with a box to practise in: the marks from Markdown · try it, one at a time. CommonMark is the markdown that most apps agree on. GitHub's markdown is CommonMark with a few extra marks, such as the checkbox, which is why the flavours on Markdown comes in flavours agree on the heading and not on the checkbox.

Read

  • Apple, If you're asked for an administrator name and password on Mac (1 min; Apple has it in many languages: choose your country or region at the bottom of the page). Apple's own words for the rule on Not mine to change: "Be sure you know which app is requesting this information." A password box on a Mac asks the same question as sudo in the terminal: may this program act as the administrator, this once? On Windows the same question comes as a Yes or No box called User Account Control. Microsoft's page on it explains it in its first two sentences: read those two, and leave the setting where it is.
  • Anthropic, How we built Claude Code auto mode (~5 min for the parts below, 2026). The company that makes Claude Code, on the second model from Who checks before it acts? Read the first four paragraphs, then skip to Results. Two numbers to find. People approve 93% of the questions the agent asks them, so a question that comes every time stops being read. And on 52 real dangerous actions, the second model let 17% through: they call it "the honest number". That is a false negative, the square on The four-square error chart where something harmful is called safe. It is the same kind of model as last week's classifier: right most of the time, not always. The same section says that if you check every action carefully yourself, auto mode is "arguably a regression".
  • National Cyber Security Centre (UK), Install the latest software and app updates (2 min). The second habit from What an attacker wants, from the UK government's cyber security agency: "If you receive a prompt to update your device (or apps), don't ignore it." The hole in sudo from class was open for almost ten years, and an update is what closed it.
  • AGENTS.md, the format's own page (1 min: the first screen). "Think of AGENTS.md as a README for agents." It is the file from And the agent? at the end of the markdown part: a README is written for people, and AGENTS.md holds what a coding agent needs to work on the project, read every time it starts. Claude Code reads a file with the same job, called CLAUDE.md. Both are markdown, and both are plain text you can open and read.

Keep

  • GitHub, Basic writing and formatting syntax (a reference, not a reading; in nine languages, from the language menu). The marks GitHub draws, which is the flavour your journal and your README are drawn in. The sections you need are Headings, Styling text, Quoting text, Lists and Task lists. One warning: its Line breaks section starts with comments and issues on GitHub, where one return does start a new line. In a .md file it does not, and a new paragraph still needs a blank line above it. When you ask an agent to write markdown, tell it where the file will be read, on GitHub or in Notion, because the marks are not the same in both.
