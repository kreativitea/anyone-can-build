Do: finish the rehearsal, both plans to a merged pull request

Work in timeline-rehearsal, your private copy of Timeline, not your older copy from the architecture classes. If you did not finish the copy in class, follow the README's Get your own copy: the new repository on GitHub must be Private and empty, and kreativitea is added as a collaborator.

For each plan, docs/plans/likes.md and then docs/plans/delete-your-post.md, the five steps from class:

  1. Plan. make worktree BRANCH=likes (or BRANCH=delete-your-post). Read the plan beside DESIGN.md and AGENTS.md. In section 5, write what you think is wrong, before any agent reads the plan.
  2. Review the plan. A new session, with docs/reviewer.md. Every objection in section 5, yours and the agent's: accept or reject, and why. Fix the plan, and commit it before any code.
  3. Build. Your agent builds from the plan. make check: is the test count the one in section 3?
  4. Review the result. A new session, on the diff (git diff main...likes). Decide each objection.
  5. Check it live. Push, open a pull request with one sentence in your own words, merge. make run, and try the feature.

Merge one plan at a time. After each merge: git pull on main, make check, and remove the worktree. The second merge may conflict in server.py, because both plans change it: ask your agent to resolve it on the second branch, run make check, and read the result before you merge.

Commit docs/prompts/ in the same pull request as the change. Never edit it. If you use an AI tool other than Claude Code, nothing saves your prompts for you: copy what you typed into a file in docs/prompts/, as its README says.

Then: one line in your tracker

Answer the question from the debrief, from your own section 5: which mistakes did your agent find, and which did you? Name one of each, if you can, and one that nobody found until the room talked about it.

Keep your data made up. No real person's name or messages in a plan, a prompt or a post.
