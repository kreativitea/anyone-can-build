Class 18 — Sources

Not homework. These are the sources behind Class 18's claims, so that any of them can be checked. The class is a workshop, and most of it is the course's own material: the four checks are the instructor's, and Gaidai Eats on Render, reporting to Sentry, was built for the course. What comes from outside is how Render, Sentry and Google Analytics behave, read in their own documentation.

Supabase, on your own app

  • Supabase's keys, row-level security and policies, its MCP server, and Resume project for a paused free project are the same as in Build vs. buy · Guided integration: Supabase; their sources are on Class 17's page. They are behind Supabase · the four checks, Gate A · Row-level security on, and a policy you can read out loud, and What to bring back.

Render

  • Gaidai Eats on Render — the site on Live: Gaidai Eats, on the internet. Its code is not public: Gaidai Eats is the midterm, and it will be the midterm again for the next class.
  • Render, Deploy for Free — Two kinds of service on Render. "Static sites are free to deploy on Render." A free web service "spins down" after 15 minutes with no traffic coming in, and starting again "takes about one minute". The page describes no sleep for a static site.
  • Render, Static Sites — the static site made at Station D: connect the repository, give the build details, and Create Static Site.
  • Render, Render MCP Server — Render · the four checks and Station C. The server can create static sites and web services, start a deploy, read logs and update environment variables. The first time Claude Code uses it, it opens a sign-in in your browser. It does not connect a GitHub repository; that part stays with you.
  • GitHub Docs, Installing a GitHub App from a third party — the choice on Station C: "select All repositories or Only select repositories". The course picks the second, the smallest access that works. Render's own page, Linking GitHub, says a deploy can fail when the app is "configured for the wrong set of repositories".
  • Render, Deploying on Render — From now on: every push is a new deploy. When you push to the linked branch, Render "automatically rebuilds and redeploys your service."

Sentry

  • Sentry, Sentry MCP Server — Sentry · the four checks and Station F. The server is at https://mcp.sentry.dev/mcp, and "All connections use OAuth": you sign in once, in the browser.
  • Sentry, Loader Script — the script tag on Station F. It is under Settings > Projects > (your project) > SDK Setup, and the page says to include it "as the first script on your page". That is why the slide says before all your other scripts.
  • Sentry, Data Source Name (DSN) — The DSN is safe to be public: "DSNs are safe to keep public because they only allow submission of new events". They "do not allow read access to any information."
  • Sentry, Data Collected — a page to check your answer at Station H against. Sentry's JavaScript SDK sends the page's URL, the browser and the operating system, and the console messages before the error. It also says: "By default, the SDK sends the user's IP address." It does not add a name or an email unless your code gives it one.
  • Personal Information Protection Commission, Act on the Protection of Personal Information — Japan's APPI, behind the question at Station H: is any of it personal information?

Google Analytics, for anyone done early

  • Google, Measurement ID — check 2 on Done early? Google Analytics · the four checks. The ID is "a unique identifier for a web data stream", and it starts with G-. You find it in the web data stream's details.
  • Google Analytics, google-analytics-mcp — check 1 on the same slide. Its tools run reports and read account details; a few can add annotations or key events to a property that already exists. None of them makes a property or a data stream, or adds the tag to your page. It also needs Google Cloud credentials.
